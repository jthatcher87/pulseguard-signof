  1. Executive Orientation & Audit Objectives

This dossier provides independent peer reviewers, security auditors, and clinical advisors with the exact mathematical, architectural, and forensic parameters required to evaluate PulseGuard™ prior to production deployment.

System Verification Mandates

  1. Mathematical Soundness: Verify that all key derivation paths, ephemeral key agreements, and token derivations are cryptographically non-converging and provide perfect forward secrecy.
  2. Zero-Knowledge Architecture: Confirm that neither cloud relays, network observers, nor local forensic acquisition can correlate an individual's diagnostic history with their social encounter graph.
  3. Volatile Memory Hygiene: Audit the sub-10ms deterministic zeroization protocol (memset_s) and OS-level shielding mechanisms.
  4. Clinical Decision Bounding: Confirm that exposure lookback windows adhere strictly to CDC transmission epidemiology without introducing alert fatigue or false positives.
  5. Reviewer Panels & Verification Scope

The peer review process is partitioned across three specialized independent panels:

PANEL 1: Cryptographic & Systems Security

  • Key Derivations & Nonce Freshness: Analysis of entropy sources and derivation uniqueness.
  • Volatile RAM Zeroization & Ghost Mode: Audit of secure memory handling and state-clearing timers.
  • OHTTP Gateway & Timing Correlation: Review of oblivious proxy implementation and traffic analysis defenses.

PANEL 2: Clinical & Public Health Epidemiology

  • CDC Lookback Periods (60d - 365d): Verification of temporal logic for different pathogens.
  • Dual-Marker Syphilis Adjudication: Review of laboratory logic for treponemal vs. non-treponemal markers.
  • Smart Truncation via Negative Anchors: Analysis of window reduction based on negative lab history.

PANEL 3: Healthcare Privacy & Regulatory Counsel

  • HIPAA Non-Covered Entity Standing: Regulatory review of organizational standing.
  • FTC Direct-to-Consumer Compliance: Verification of consumer health data privacy adherence.
  • Impossibility of Subpoena Compliance: Audit of technical constraints preventing third-party data extraction.
  1. Formal Threat Model & Adversarial Boundaries

3.1 In-Scope Threat Vectors (Adversarial Posture)

PulseGuard explicitly defends against adversaries with the following capabilities:

  • Compromised Host OS / Malicious Background Task: Rogue applications or compromised system window managers attempting to screenshot the screen buffer or read suspended application memory.
  • Device Physical Seizure & Forensic Acquisition: State actors, forensic technicians (e.g., Cellebrite, GrayKey), or malicious thieves dumping flash memory or acquiring unencrypted cold RAM.
  • Hostile / Subpoenaed Public Relay: Malicious cloud operators, compromised Redis bulletin targets, or third-party subpoenas attempting to reconstruct social contact graphs or identify patient identities.
  • Untrusted Network Observer (ISP / Rogue Wi-Fi / IMSI Catcher): Eavesdroppers intercepting cellular or Wi-Fi traffic attempting to correlate clinical visits with user IP addresses.
  • Malicious Trolls / Sybil Ingestion Attacks: Bad actors broadcasting false positive alerts to trigger community panic or disrupt specific individuals.

3.2 Out-of-Scope Threat Boundaries

The system explicitly considers the following vectors outside its defensive perimeter:

  • Active Hardware Decapping & Micro-probing: Direct destructive electron-microscope probing of silicon dies inside the Apple SEP or Android StrongBox coprocessors during live cryptographic execution.
  • Full Host OS Kernel Compromise with Active Kernel-Level Keyloggers: A rooted/jailbroken device where a persistent kernel exploit actively intercepts raw hardware display frames and touch events in real time.
  1. Targeted Reviewer Inquiries & Questionnaire

Peer reviewers are requested to provide formal findings on the following specific inquiries:

Track 1: Cryptography & Key Management

  1. Ephemeral X25519 Token Freshness: Does the dynamic key agreement protocol (Curve25519 ECDH + 128-bit timestamp nonce N_t + context string) provide adequate mathematical resistance against replay, precomputation, and multi-user collision across a global user base?
  2. Domain Separation via HKDF-SHA-256: Are the derivation paths (m/0'/health', m/0'/tokens', m/0'/auth') mathematically non-converging such that a compromise of K_{tokens} provides zero advantage in recovering records encrypted under K_{health}?
  3. AES-256-GCM Nonce Lifetime: Does the 96-bit CSPRNG IV selection guarantee that nonce reuse probability remains < 2^{-32} over the maximum anticipated database record lifetime?

Track 2: Volatile Memory Hygiene & Anti-Forensics

  1. Compiler Optimization Resilience: Does the 3-pass zeroization routine (memset_s preceded by entropy and inverted bitmask overwrites) guarantee immunity from dead-store compiler optimization across LLVM/Clang and GCC AOT compilation?
  2. Ghost Mode 15-Second Grace Window: Does the 15-second ephemeral in-memory timer expose an unacceptable window of vulnerability to physical cold-boot memory dumps, or does the default "Zero-Tolerance Lock (0s)" provide sufficient enterprise risk mitigation?
  3. GazeGuard Front-Camera Activation: Does edge NPU inference for shoulder-surfer detection introduce any side-channel timing leakage into volatile cryptographic state?

Track 3: Relay Anonymity & Network Privacy

  1. OHTTP Gateway Metadata Stripping: Does the RFC 9292 / 9458 Oblivious HTTP gateway topology successfully prevent the target bulletin board from correlating client IP addresses with published manifests?
  2. Timing Correlation Resistance: Is the 1-to-4 hour randomized transmission jitter window sufficient to defeat statistical traffic analysis by an ISP observing both client outbound requests and relay ingress?
  3. Hashcash Proof-of-Work Difficulty: Is the 20-bit Hashcash challenge (~2 seconds of client CPU computation) an optimal balance between battery preservation and Sybil denial-of-service prevention?

Track 4: Clinical Decision Logic & Smart Truncation

  1. Smart Truncation Safety: For Tier 3 infections (HIV, Latent Syphilis, HBV, HCV), does truncating the lookback window to the date of a verified negative lab test introduce any clinical blind spots regarding seroconversion eclipse periods?
  2. Syphilis Serofast Protocol: Does the dual-marker adjudication rule (requiring quantitative RPR titer confirmation and checking baseline serofast anchors) effectively eliminate false positive partner notifications from lifetime treponemal antibodies?
